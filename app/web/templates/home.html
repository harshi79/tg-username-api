↗Telegram Check

Public resolution on t.me with entity typing — channel, group, bot or bare user page — plus redirect, 404 and rate-limit handling.

◇Fragment Intelligence

Collectible state from Fragment's public pages: taken, on auction, for sale, sold — with publicly displayed TON prices and bids, column-aligned from source tables.

≡Bulk Check

Up to 15 usernames per request, checked concurrently with bounded upstream concurrency and in-flight deduplication. Input order preserved.

⚙Detailed Reports

Objective username characteristics (length, digits, underscores, repetition), public signals, and a clearly-labelled heuristic — never a market valuation.

Status model

Every check ends in exactly one verdict. The API only reports available when Telegram clearly does not resolve the handle and Fragment has no listing. Anything ambiguous becomes unknown — including timeouts, rate limits and redesigned upstream pages.

StatusMeaning
taken Currently resolves on Telegram (channel / group / bot page, or a Fragment "claimed" report consistent with a bare user page).
fragment_collectible Not publicly resolving, but Fragment tracks it as a collectible — auction, sale, sold or held. Not freely claimable.
available Clean negative on Telegram (404 / telegram.org redirect) and no Fragment page, with no upstream failures.
invalid Failed local validation. No external request was made.
unknown The API could not safely determine the state. Never assume availability from this status.

Rate limits

25 requests per IP per minute on /api/*, with X-RateLimit-Limit, X-RateLimit-Remaining and X-RateLimit-Reset response headers. Bulk requests accept a maximum of 15 usernames and count as one API request. This website's pages are not rate limited. On serverless platforms the in-memory limiter is best-effort per instance — see the docs.
